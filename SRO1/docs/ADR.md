# ADR-001. Выбор Apache Cassandra для хранения GPS-событий транспорта

- **Статус:** принято
- **Дата:** 2026-10-20

## Контекст
Автопарк передаёт GPS-события (до 1 Гц с машины). Нагрузка: поток записей, неизменяемые события,
запросы известны заранее и всегда содержат машину и время («трек за день», «последняя позиция»).
Данные нужно хранить 90 дней и масштабировать при росте парка.

## Рассмотренные варианты
| Критерий | Cassandra | PostgreSQL + TimescaleDB/PostGIS | MongoDB time-series |
|---|---|---|---|
| Запись потока | Отлично, линейное масштабирование | Хорошо на одном узле | Хорошо |
| Чтение «машина + день» | Одна партиция, упорядочена | Индекс/hypertable | Хорошо |
| Гео-запросы | Слабо | Отлично (PostGIS) | Хорошо |
| Ad hoc аналитика, JOIN | Нет | Отлично | Средне |
| TTL / удаление старых данных | Встроенный TTL + TWCS | Политики retention | TTL-коллекции |
| Операционная сложность | Выше | Ниже | Средняя |

## Решение
Cassandra. Модель строится от запросов (query-first), ключ партиции `((vehicle_id, day), event_ts)`,
`CLUSTERING ORDER BY (event_ts DESC)`, TTL 90 дней, `TimeWindowCompactionStrategy` с окном 1 день.

## Обоснование
1. Запись масштабируется добавлением узлов; запись в LSM-дереве дешёвая.
2. Запрос «машина + день» читает одну партицию, строки уже отсортированы; `LIMIT N` читает голову партиции.
3. Ключ с `day` ограничивает рост партиции; при частоте >1 Гц добавляется `hour` (см. `scripts/partition_size.py`).
4. События не обновляются, поэтому TWCS и TTL дают дешёвое удаление целых SSTable.
5. Идемпотентный upsert защищает от дублей при повторной доставке.

## Последствия
- (+) Предсказуемая задержка, горизонтальное масштабирование, простое устаревание данных.
- (−) Нет JOIN и произвольных фильтров; каждый запрос требует своей таблицы (денормализация).
- (−) Гео-поиск («машины в радиусе») не поддерживается, нужна вторая система (PostGIS/Elastic).
- (−) Суточные сводки и «последняя позиция» поддерживаются приложением при записи.
- (−) Сутки считаются по UTC; клиент (Алматы, UTC+5) должен переводить границы запроса.

## Риски и меры
| Риск | Мера |
|---|---|
| Широкие партиции при высокой частоте | Бакетирование по часу; мониторинг `nodetool tablehistograms` |
| Запоздавшие события | `USING TIMESTAMP` = время события для `last_position` |
| Tombstone при удалении суток | Удаляем партицию целиком одним DELETE; предпочитаем TTL |
